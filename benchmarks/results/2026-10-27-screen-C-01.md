# screen-C-01: first agent run, screen-flow skill (automatic layout)

Brief: `benchmarks/briefs/screen.md` (52 items, 77 connections, 7 groups). One fresh agent got only the `Brief` text and the screen-flow skill, version 0.11.0. A first agent was started but stayed in plan mode and drew nothing; this is the second.

## What happened

- Path: `flow.py build` with the screen-flow skill, not the author kit. The skill itself says more than about 25 items is a case for the author kit.
- Four build rounds, each followed by a look at the picture. Errors per round: 2, 37, 39, 27. The agent generated the spec with a script.
- Final check: **27 errors** (22 `line-through-node`, 5 `label-covers`) and **50 warnings** (mostly `lines-cross`, plus `lines-overlap`, 3 `text-may-not-fit` on the diamonds, 5 `label-too-long`, 1 `crosses-border`).
- Workarounds: `route: elbow` on far returns and HomeMap in its own row cut errors from 39 to 27; the router still cannot go around frames.

## What the picture shows (read by the lead, `r4s.png` of the run)

Present: phone and desktop frames, the three decisions as diamonds, three green entry pills, dark user chips and slate system chips with icons, tinted zones with pill labels, the web portal as its own zone at the bottom, blue happy path, rose failure.

Wrong:
- Long return lines (`NoDriversFound` to `RideOptions`, `PaymentFailed` to `TipDriver`, `Delete account` to `Splash`, `TripHistory` to `HomeMap`, `SosEmergency` to `InTrip`) run straight through frames, several screens long, and through zones.
- Onboarding is laid out in a snake that makes `HasSessionCheck` to `HomeMap` and `Allow or Skip` cross the whole page.
- Chips collide on frames (`tap Confirm`, `tap Change ride`, `tap Retry`).
- The page is about 4000 by 5000 px, so labels are small; every screen is L1 "content TBD" (no fidelity mix was asked for in the brief).
- Id chips repeat the screen name (the agent gave no `code`).
- Not counted in the picture: the agent confirmed all 52 items and 77 connections are in the spec, not that each is drawn.

## Conclusion

The automatic screen-flow layout does not hold at 52 items with this many returns. Next steps to try: (1) have the skill say at the top that a flow of this size goes through `/flow:author`; (2) run the same brief through the author kit and compare; (3) fix the router so a return line goes around frames, or lay long returns in a strip as the design says ("back arrows run in a strip above the main row").
