# Routing of 0.21.0 (the entry skill `flow:draw`) against 0.20.0

Date: 2026-11-27. Set, harness and rule: `benchmarks/routing/` (rule committed in `c90ee95`, changed to Sonnet only in `57dd253` before any baseline finished). Every run: Sonnet (`claude-sonnet-5-5`), stopped at its first decisive event. Plugin versions: 0.20.0 (`57dd253`) and 0.21.0 (`a1cd317`). Reviewed by an independent agent at the design, the plan and the diff.

## Verdict

**By the rule: kept.** On the held split, misses fell from 10 to 3 of 30, false positives stayed at 0 of 16, and in the clean environment hits rose from 11 to 14 of 15. A second run of 0.20.0 on the held split after the final runs, under the same harness, gave 21 of 30 (9 misses), so the gain is not drift over time and passes against either baseline. Per held request the new version has the higher hit rate on 5 and the lower on none (one-sided sign test, p about 0.03).

**What made the gain is not known.** `flow:draw` was loaded in 2 of 46 final held runs; the other new hits went straight to a type skill. Two readings, neither tested:

- *The PNG promise.* The gains sit on p18, p03, p08, p07 and p02, mostly where 0.20.0 gave up on Flow to make an image itself (p18: `own:png` in 3 of 4 old runs, `flow:gantt` in 2 of 2 new ones, with Gantt's description unchanged). The only text in the listing that says Flow can deliver a PNG is the new description. It can be tested on new requests by taking the PNG clause out of that description.
- *The verbs.* One description saying "draw, show, picture, visualise ... from any input" may make the whole plugin look like the tool. Weaker: the fresh "show me" and "help me see" requests gained nothing.

Lower prior, not excluded because the rows record only whether Flow was listed, not the listing: the version bump, a changed listing order, or another description cut short now that one more skill is listed.

## What is left

- **Open design question: when should the agent offer or include a picture it was not asked for?** Every fresh miss (8) is a text answer to requests like "show me what happens from the moment a refund is requested", "help me see how the services talk to each other", "I keep mixing up who talks to whom". The agent reads the code and explains it in markdown without considering a picture. Several are relational questions, where a picture answers better than prose, so this is a gap against "work well on any input", not only a product choice. Nothing was changed for it. A test of any change needs paired negatives: questions where words are the better answer (like n02), or it will reward drawing everything.
- **The hosted `Artifact` tool** of this cloud harness took p15 in every run (its instructions say to call it first for any page). A user's own install does not have it; not addressed.
- **Not measured:** whether a run that loads Flow stays with it to the end, and any model but Sonnet.

## Validity notes

- The per-request decisions of the held baseline were printed once while summarising; no held log was read before the final run, and `flow:draw` was designed from the dev logs.
- The requests and the description share a writer, so the held split is not independent of the description's words. The fresh set was meant to check that, but it is uninformative: every fresh request scored 2 of 2 or 0 of 2 on both versions alike, and none asks for an image, so no request was left where a gain could show.
- `rescore.py` replayed the baseline under the harness's later rule for shell redirects: four runs changed label (`own:svg` to `own:bash`), no total changed. Loading `flow:draw` was made non-decisive, which is stricter on the new version.
- Cost: about 270 runs, roughly $20, plus the reviews.
