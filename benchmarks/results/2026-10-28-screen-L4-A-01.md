# screen-L4-A-01: first run, a Sonnet agent, plugin 0.13.0 with the capture script

Brief: `benchmarks/briefs/screen-l4.md`. One fresh Sonnet agent got the `Brief` text (with the source folder and the address filled in) and the screen-flow skill, with `benchmarks/`, `examples/`, `docs/`, `tests/`, the changelog and the git history closed. The Angular Conduit app had been built from source and was served at `http://127.0.0.1:4200`; the agent did not build it.

## Result

- **Capture**: 12 desktop screenshots (1280 x 800) from the running app, two capture runs. The agent wrote its own plan for `capture.js`: a session that registers a made-up account and publishes one article, `remember` for the article's slug, 38 hotspots, 0 missing. The second run only dropped two hotspots that lay below the fold (they made the build warn `hotspot-outside`).
- **Diagram**: 4 build and look rounds. Final check: **0 errors, 30 warnings** (22 `lines-cross`, 8 `label-too-long`). Page 2147 x 2842 px.
- **Content**: 12 screens, 6 decisions, 2 entry points, 43 transitions, each with the file of the code it was read from. All 29 connections of the brief's structure are drawn, the four sign-in and sign-up ones through a decision ("Sign-in ok?", "Sign-up ok?") and the editor and settings saves through "Article saved?" and "Settings saved?". That makes more lines than the brief's 29, and the agent added more from the code: failure exits of the forms, the favourite button and the comment area leading to Sign up, Sign in with a wrong password back to Sign up, the author's name to the profile, and a start decision on the stored session. The screen codes differ from the brief's table (the brief text gives none).
- The top bar on every page is drawn once, from the home page, and `desc` says so.
- About 8 minutes.

Read by the lead (the final picture): both zones, the entry column with two route-guard diamonds, the blue main path from the site through Sign in to the editor and the article. The screenshots are recognisable but cannot be read at 240 px wide; red dots crowd on the home pages.

## Weak spots (the agent's own reading)

- 22 crossings; five or six arrows into the same edge of Sign in and Sign up; two arrows from Home to Sign up side by side.
- The logout line runs across the signed-in block.
- 8 phrases over 20 characters (`click Edit Profile Settings`); the agent kept them rather than use codes.
- Viewport-only screenshots lose what is below the fold (the comment area).
- Empty forms show the submit button disabled, so the red dot sits on a faded button.
- Not done: the zoom view in the HTML was not tried, the draw.io file was not opened, and the failure states were drawn from the code without being captured.

## Gaps the agent hit, and what changed (0.14.0)

1. No full-page capture: `capture.js` takes `"full_page": true` per screen. The width check replaces the shape check (`capture-width`), so a tall page passes.
2. `require('playwright')` did not resolve from the plugin folder: `capture.js` falls back to the global `npm root`.
3. `-o` of `flow.py build` was not in the skill: added.
4. The build printed no total: the report ends with `check: N errors, M warnings`.
5. Screenshots too small to read: `"size": "large"` draws a screen at twice its device size. Tried on this run's spec: 3400 x 3522 px, 0 errors.
6. Found by the lead while checking: a scene built from a relative folder kept relative image paths, so `flow.py check` from another folder reported every screenshot missing. The paths are now made absolute.
7. Open: two entry decisions in one column can run their lines on top of each other; two arrows between the same pair of screens are told apart only by position; a top bar cannot be drawn once as a bus on the web, as tab bars are.
