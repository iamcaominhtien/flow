SQL or NoSQL?
Two ways to store data. Neither is better; they fit different jobs. Read across each row to compare.
SQL database
Data in tables with fixed columns, linked by keys.
NoSQL database
Data as flexible documents, each shaped as it needs.
vs
Shape of the data
Every row has the same columns.
Each document can have its own fields.
Changing the shape
A planned change to the table, applied to all rows.
Just start writing the new field.
Links between things
Strong: keys and joins keep them consistent.
Weak: you repeat data or link it yourself.
Growing very large
Harder: usually one big machine, then careful splitting.
Easier: designed to spread over many machines.
Best for
Orders, accounts, money: data that must stay exact.
Feeds, logs, catalogues: lots of data that changes shape.
Rule of thumb
Start with SQL when the data has clear relationships and must stay correct. Add NoSQL beside it when one kind of data is huge or its shape keeps changing. Many systems use both.
